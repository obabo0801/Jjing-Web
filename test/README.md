# 검증

- `npm run lint`: 서버·브라우저·Service Worker 환경을 구분해 검사합니다. 파일은 수정하지 않습니다.
- `npm run format:check`: 기존 서식과 다른 파일을 알려 줍니다. 자동 수정하지 않습니다.
- `npm test`: Node 내장 테스트를 실행합니다. 운영 DB·업로드 파일·외부 API는 사용하지 않습니다.
- `npm run check`: lint와 테스트를 순서대로 실행합니다. 서식 검사는 별도로 실행합니다.

현재 테스트는 권한 규칙, 필수 동의, 중복 실행 방지, 쿠키 검증, 시작 환경 검사, 사용자 라우트, API 응답 계약을 확인합니다. 사용자 라우트는 테스트 전용 로컬 HTTP 서버와 메모리 SQLite를 사용하고, 접속 로그 저장은 대체합니다. 실제 운영 서버·기기·브라우저 검증을 대신하지 않습니다.

프로필 회귀 테스트도 포함합니다.

- 요청 처리: `profile-routes.test.js`는 실제 프로필 라우터를 테스트 전용 로컬 HTTP 서버와 메모리 SQLite에 연결합니다. 생성·완료·이미지·QR 링크·조회·차단·권한 요청의 응답과 라우트 순서를 검사합니다. 서명 검증 후의 UID를 주입하며, 이미지 저장·관리 서비스·접속 로그·이벤트 전달은 대체합니다. 실제 쿠키 서명은 별도 쿠키·사용자 테스트에서 검증합니다.
- QR 업로드: 로컬 HTTP와 메모리 이미지로 원본·편집·GIF·만료·15MB 제한을 검사합니다. DB·관리 기능·이벤트 전달은 대체하며 파일을 저장하지 않습니다.
- 닉네임 검사: 실제 editor 모듈에 최소 DOM·레이어·API 대체 구현과 가상 타이머를 연결합니다. 대기·실패·응답 순서·닫기 동작을 검사하며, 실제 브라우저의 레이아웃·이벤트 통합 검증은 별도로 필요합니다.
- 이미지 선택: `profile-portrait.test.js`에서 실제 `profile/image.js`의 저장·취소·초기화·원본 재조절·QR 수신·임시 URL 정리를 검사합니다. DOM·조절 창·수신 이벤트·URL은 대체하므로 실제 제스처·QR 스캔은 기기에서 별도로 확인해야 합니다.
- 프로필 화면: `profile-view.test.js`는 실제 view·actions·label·line 모듈의 표시·실시간 갱신·차단 사유·중복 실행 방지·채팅 이벤트를 검사합니다. DOM·레이어·API·권한 편집 컴포넌트는 대체하므로 실제 배치·포커스·권한 편집 동작은 별도로 확인해야 합니다.

`shared.test.js`·`build.test.js`는 공용 규칙과 기존 API/hash/프록시 계약을 검사합니다. 빌드 플러그인은 메모리 내 가짜 산출물로 실행하므로 `dist`를 쓰지 않습니다. `imports.test.js`는 서버→화면 코드, 서버→빌드 플러그인 등 역방향 import를 ESLint가 거부하는지 확인합니다.

`build-output.test.js`는 실제 Vite 설정과 플러그인으로 메모리 빌드(`write: false`)를 실행합니다. HTML 매핑·JS와 CSS 자산·청크 참조·data-* 변환·페이지별 CSS 연결을 확인합니다. 설정 파일의 임시 번들과 `dist`는 쓰지 않으며, public 파일 복사·서버의 HTTP 제공·브라우저 실행은 검증하지 않습니다. 디스크 산출물 생성은 `npm run build`로 별도 확인합니다.

`i18n-routes.test.js`는 실제 번역 라우터와 로컬 번역 파일을 테스트 전용 HTTP 서버에 연결합니다. Web Crypto로 계산한 hash와 서버의 언어 파일명·번역 키가 일치하는지, 오프라인 번역·시스템 언어·잘못된 요청 처리를 확인합니다. 운영 서버·DB·외부 번역 API는 사용하지 않습니다.

`sqlite.test.js`는 OS 임시 폴더의 테스트 전용 DB로 실제 SQLite 시작 코드를 실행합니다. 신규 생성, 기존 데이터 보존, 누락 열 추가, 역할 확장 백업, 인덱스·트리거 보존, 반복 시작, 권한 회수, 실패 시 롤백을 검사합니다. 각 실행의 저장 경로를 임시 폴더로 대체하고 종료 후 해당 폴더만 삭제합니다. 운영 `data/service.db`는 열지 않습니다.

`service.test.js`는 서비스 import 경로, 프로필 링크 만료·연장, SSE 전송·접속 상태, 번역 로딩, 로그 시각·기록 값을 검사합니다. 메모리 상태와 대체 응답·기록 함수를 사용하며, 운영 DB·로그 파일에 쓰거나 알림·음성 외부 API를 호출하지 않습니다.

`manage.test.js`는 실제 관리 서비스와 SQLite 연결·차단 로그 코드를 테스트별 임시 폴더에서 실행합니다. 권한 검사·부여·회수, 공유 IP 차단 해제 제한, 동시 요청, 로그·데이터 저장 실패 시 롤백과 재시도를 검사합니다. 저장 경로와 시각만 대체하고 임시 DB는 종료 후 삭제합니다. 전원 차단·프로세스 강제 종료 시 복구 검증은 포함하지 않습니다.

`image.test.js`는 실제 이미지 변환·저장 코드를 임시 폴더에서 실행합니다. 원본 바이트·hash URL·썸네일·EXIF 방향·GIF 프레임과 재생 정보·원형/사각형 회전·변환 크기 제한·중복 저장을 검사합니다. 테스트 이미지와 임시 저장 파일은 종료 후 삭제하며, 실제 브라우저 미리보기와 제스처 검증은 포함하지 않습니다.

`speech.test.js`는 실제 TTS·캐시·STT 저장·음성 인식 모듈에 대체 SDK·fetch·메모리 파일·DB를 연결합니다. 합성 요청 정규화·캐시 키·동시 요청·대체 합성·재시도·초기화 시간 초과·저장 실패 정리·인식 응답 조합을 검사합니다. 테스트 프로세스 안에서만 모드와 가짜 인증 경로를 지정하며 실제 계정·외부 API·음성 파일은 사용하지 않습니다. 실제 음질·인식률·인증 연동 검증은 포함하지 않습니다.

`init.test.js`는 하위 기능을 대체하여 초기화 순서·로딩 반환·중복 실행 방지를 확인합니다. `mount.test.js`는 최소 DOM 구현에서 실제 컴포넌트의 범위 탐색, 전역 이벤트 등록 분리, 중첩 요소 처리, 재마운트와 값 변경을 검사합니다. 채팅·음향·레이어 호출 등은 대체하므로 실제 브라우저의 배치·포커스·터치 검증을 대신하지 않습니다.

`pwa.test.js`는 Worker 등록·Push 구독·해제·권한·직접 알림·동기화 요청을 대체 브라우저 API로 검사합니다. 테스트에서만 Vite의 `import.meta.env.PROD`를 제어 가능한 값으로 바꿉니다. `worker.test.js`는 실제 Worker 소스를 격리된 VM에서 실행하여 큐 재전송·오프라인 응답·알림 메시지·클릭 URL 제한을 확인합니다. 네트워크·IndexedDB·캐시·알림은 대체하며 실제 권한·구독·설치 상태를 변경하지 않습니다.

## 알려진 문제

사용 예정 기능의 실패 경로도 검사합니다. `pwa.test.js`는 큐 저장의 동기 예외·오류·중단 시 연결 정리, Worker 미준비·예약 실패 시 큐 유지, 직접 알림 실패 반환을 확인합니다. `worker.test.js`는 겹친 동기화의 작업 공유, 처리 중 추가된 요청과 실패 후 재시도를 검사합니다. 프로세스 종료·서버 처리 후 응답 유실에 대한 중복 방지를 보장하는 검사는 아닙니다.

`data.test.js`는 대체 저장소에서 실제 `clearData()`·`storage.clear()`를 실행합니다. 일부 삭제 실패는 `false`, 삭제 완료·캐시 부재는 `true`인지와 다른 저장소의 정리·연결 해제를 검사합니다. 실제 사용자 데이터를 지우지 않습니다. `meter.test.js`는 대체 AudioContext·프레임 예약으로 중지 전·콜백 내부·실행 후 중지와 반복 해제를 검사하며 마이크를 열지 않습니다.

`styles.test.js`는 Vite의 HTML 진입점을 기준으로 공통·페이지 CSS 연결 순서, 파일 누락·중복·순환 import와 미연결 CSS를 검사합니다. 페이지 전용 규칙이 공통 CSS로 돌아오지 않는지, 동적 컴포넌트 스타일이 남아 있는지도 확인합니다. 현재 따옴표로 지정된 HTML link·CSS @import를 대상으로 하며, selector의 실제 사용 여부나 브라우저의 배치·캐스케이드를 판정하는 검사는 아닙니다.

secret 누락 시 일반 쿠키 거부 검사는 보안 수정 후 일반 회귀 테스트로 전환했습니다. 공유 IP의 다른 사용자·관리자를 복원하거나 강등하지 않는지, 서명된 사용자는 IP가 바뀌어도 유지되는지도 검사합니다.

`no-unused-vars`와 `no-use-before-define`은 기존 경고를 정리한 뒤 오류 수준으로 강화했습니다. 함수 선언문의 전방 참조와 사용 예정인 공개 export는 허용합니다. `imports.test.js`에서 이 기준과 미정의 변수·도달 불가능한 코드·중복 키 등의 오류 처리를 확인합니다.

`theme.test.js`는 대체 DOM에서 테마·메타 색상 동기화, 이벤트 중복 등록 방지, 뷰어 색상 우선 적용과 복원을 검사합니다. 실제 브라우저·PWA 상태바 동작을 대신하지 않습니다.

`select.test.js`는 대체 DOM·레이어에서 기본 떠 있는 메뉴, 위·아래 위치 계산, `data-expand`, 선택 이벤트, 키보드 이동, 제거 시 정리, wearable 전체화면 우선순위와 중복 열기·취소를 검사합니다. 실제 배치·클리핑·터치 스와이프는 브라우저와 기기에서 별도로 확인합니다.

`mount → toggle → drawer → layer → mount` 등의 순환은 컴포넌트 등록을 `src/js/init.js`로 옮겨 해소했습니다. 전역 이벤트처럼 한 번만 실행할 기능은 init에서 호출하고, 새 DOM에도 적용할 준비 함수는 init의 `register(...)` 목록에 추가합니다. 공통 `mount(root)`는 등록된 함수를 같은 순서로 동기 실행하며 컴포넌트를 직접 import하지 않습니다. 초기화 전 호출은 오류로 알립니다.

`mount-register.test.js`는 등록 순서·중복 등록 방지·반복 실행·오류 전달을 검사합니다. `dependencies.test.js`는 브라우저 소스의 정적 import·재export·문자열 동적 import를 분석해 순환을 거부합니다. 런타임에 계산되는 import 경로와 외부 패키지 내부의 의존성은 검사하지 않습니다.
